# svg2hvif — перевод значков HeOS из SVG в HVIF

HVIF (`BEOS:ICON`, тип `VICN`) — векторный формат значков системы. Инструмент берёт SVG из `design/icons/` и делает:
- `.hvif`;
- ресурс `.rdef` для приложений;
- массив C++ для встроенных значков.

Ещё он умеет обратный перевод HVIF → SVG, чтобы проверить результат на любом компьютере.

Формат сверен с исходниками Haiku (лицензия MIT):
- `FlatIconFormat.cpp`, `FlatIconImporter.cpp`, `PathCommandQueue.cpp`;
- `IconRenderer.cpp` и SVG-импорт Icon-O-Matic.

Код написан заново.

## Быстрый старт

```
pip install fonttools          # нужен только для значков с <text>
python svg2hvif.py ../../icons -o ../../icons/hvif
python svg2hvif.py ../../icons/apps -o ../../icons/hvif/apps --format hvif,rdef
python svg2hvif.py --decode ../../icons/hvif/apps/tracker.hvif -o tracker.preview.svg
```

| Ключ | Что делает |
| --- | --- |
| `--format hvif,rdef,cpp,preview` | какие файлы писать: `.hvif`, `.rdef` (`resource vector_icon`), `.icon.h` (массив `uint8`), `.preview.svg` (расшифровка обратно) |
| `--fonts DIR` | где искать шрифты для `<text>`. По умолчанию `design/fonts` |
| `--no-shadows` | не имитировать `feDropShadow` |
| `--hinting auto\|on\|off` | флаг выравнивания по пикселям. `auto` ставит его там, где в SVG `shape-rendering="crispEdges"` (мелкие значки) |
| `--current-color #F2F4F8` | цвет для `currentColor` |
| `--decode` | HVIF → SVG |

После записи каждый файл расшифровывается обратно. Если в нём остался хоть один лишний байт, это ошибка.

## Таблица соответствия SVG → HVIF

✅ — переводится точно · ≈ — приближённо · ❌ — не поддерживается, нужна правка в SVG

| SVG | В HVIF | Как переводит конвертер | |
| --- | --- | --- | --- |
| `viewBox` | холст 64×64 единицы | масштаб `64 / max(ширина, высота)`, по центру | ✅ |
| `<path>`: M L H V C S Z | путь: точки с ручками «вход/выход» | один к одному | ✅ |
| `<path>`: Q T | — (только кубические) | квадратичная кривая → кубическая без потерь | ✅ |
| `<path>`: A (дуги) | — | дуга → кубические кривые, куски ≤ 90° | ✅ |
| `rect` (и `rx/ry`), `circle`, `ellipse`, `line`, `polyline`, `polygon` | путь | переводятся в путь | ✅ |
| `g`, `transform` (matrix, translate, scale, rotate, skewX/Y) | — | вшиваются в координаты | ✅ |
| `use`, `defs`, `symbol` | — | разворачиваются в копии | ✅ |
| Цвет: `#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()`, имена, `currentColor` | стиль «цвет» | серые и непрозрачные цвета пишутся короче (1–3 байта) | ✅ |
| `opacity`, `fill-opacity`, `stroke-opacity` | альфа цвета | перемножаются в альфу | ✅ / ≈ |
| `linearGradient` | градиент «линейный», ось −64…64 + матрица | точная матрица, учитываются `gradientUnits` и `gradientTransform` | ✅ |
| `radialGradient` | градиент «круговой», радиус 64 + матрица | центр и радиус точно | ✅ |
| `radialGradient fx/fy` (смещённый фокус) | — | фокус берётся в центре | ≈ |
| `stop-color`, `stop-opacity`, `offset` | точки градиента (позиция 0…255) | точность позиции 1/255 | ✅ |
| `spreadMethod="reflect/repeat"` | только продолжение крайних цветов | будет `pad` | ❌ |
| `href` между градиентами | — | наследование разворачивается | ✅ |
| `stroke`, `stroke-width` | преобразователь «обводка», ширина — **целое** число | дробная ширина: путь хранится в масштабе ×2…×4, фигура уменьшает его обратно — ширина точная | ✅ |
| `stroke-linejoin` miter / round / bevel | то же | то же | ✅ |
| `stroke-linecap` butt / round / square | то же | то же | ✅ |
| `stroke-miterlimit` | целое 1…255 | округляется | ✅ |
| Обводка градиентом | стиль-градиент у фигуры с обводкой | матрица пересчитывается в пространство пути | ✅ |
| `stroke-dasharray` | — | рисуется сплошной | ❌ |
| `fill-rule="evenodd"` | только nonzero | вложенные контуры переворачиваются по чётности вложенности. Самопересекающиеся контуры не исправить | ≈ |
| `<text>`, `<tspan>` | — | переводятся в кривые через fontTools по шрифтам `design/fonts`. Без кернинга и лигатур | ≈ |
| `feDropShadow` | — | 2 полупрозрачных слоя со сдвигом: мягкий край обводкой и ядро. Без размытия | ≈ |
| `feGaussianBlur` (свечение) и прочие фильтры | — | пропускаются | ❌ |
| `clipPath`, `mask` | — | пропускаются, режьте геометрию в редакторе | ❌ |
| `pattern`, `image`, `foreignObject` | — | пропускаются | ❌ |
| `shape-rendering="crispEdges"` | флаг фигуры «hinting» | ставится автоматически | ✅ |
| `display:none`, `visibility:hidden` | — | не попадают в файл | ✅ |
| — | уровни детализации LOD (видимость по масштабу) | не задаются. Упрощённые версии для 16 px — в Icon-O-Matic | — |

**Ограничения HVIF:**
- не больше 255 стилей, 255 путей и 255 фигур на значок;
- не больше 255 точек в пути;
- координаты от −128 до 192 с шагом 1/102. Целые от −32 до 95 занимают 1 байт;
- матрицы хранятся 24-битными числами, точность примерно 5 знаков;
- цвета 8-битные.

## Как рисовать SVG, чтобы перевод был точным
1. Холст 64×64 или кратный ему (128, 16, 24). Тогда точки ложатся на целые координаты и занимают 1 байт.
2. Тени и блики рисуйте отдельными полупрозрачными фигурами. Фильтры HVIF не понимает.
3. Подписи на значках (`PDF`, `HGRPH`) лучше сразу перевести в кривые. Конвертер умеет это сам, но ему нужен fontTools.
4. Без `clipPath`, `mask`, `pattern`, растровых картинок и пунктира.
5. Толщина обводки после масштаба до 64 должна быть кратна 0,25. Тогда она переводится без округления.

## Проверка
Все 132 значка из `design/icons` переведены без ошибок. Итог: 92 КБ, значок приложения — 0,5–1,2 КБ.

Сверка: оригинал и расшифровка `.hvif` отрисованы в Chrome на 96 px.
- Средняя разница по пикселям — около 1 уровня из 255.
- Наибольшие отличия — у значков с тенями (приближение без размытия): 2–4 уровня.

Декодер дополнительно проверен на настоящих значках Haiku (StyledEdit, Terminal, MediaPlayer, Icon-O-Matic): они расшифровываются и выглядят правильно.

**Не проверено на самой HeOS:** превью рисует Chrome, а не `IconRenderer`. Сглаживание, флаг hinting и гамма в системе будут немного отличаться. Перед выпуском откройте несколько `.hvif` в Icon-O-Matic и в Tracker.

## Куда класть результат
- **Приложения:** `icons/hvif/apps/<имя>.rdef` вставить в `.rdef` приложения (`resource vector_icon { … };`). Затем, как обычно, `rc` → `xres`.
- **Типы файлов:** `.hvif` записывается в атрибут `META:ICON` (тип `VICN`) MIME-типа. Для отдельных файлов — в `BEOS:ICON`.
- **Встроенные значки в коде:** `--format cpp`, затем `BIconUtils::GetVectorIcon(data, size, bitmap)`.
- Названия атрибутов и тип взяты из `FlatIconFormat.cpp`. Команду установки для вашей сборки уточните на системе.
